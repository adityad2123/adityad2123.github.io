Project 2: Fun with Filters and Frequencies

1.1

Here’s the convolution implementation with 4 loops. We first ensure that our kernel is 2-dimensional, and it has odd heights and widths to ensure the convolution is symmetric. We implement same padding; this requires padding the image before convolution with the kernel height or width, subtracted by 1, then integer-divided by 2. This makes sense; with a 3x3 kernel, we want to add 1 extra space on each side of the image so that our image ends up being the same side once the convolution is done. That way, the first convolution will be on the square with diagonal (0, 0) to (2, 2), centered at (1, 1) on the padded image → which is (0, 0) on the initial image.

For convolution, we must flip the kernel. Then, we essentially iterate through each image pixel (with i for height and j for width). At each image pixel, we apply the kernel by iterating through the kernel height and kernel width, and adding the pixel value there scaled by the corresponding flipped kernel value to a running total. This running total, after the full dot product operation, gets placed on our final_image, which starts out as a 2D array of 0s but is filled after the operation.

This implementation on the image of me was relatively slow, at 5.8513s.

The convolve function with 2 loops is largely the same, except we use vectorization for our dot product. Once we have the i, j corresponding to the pixel we’d like to apply the kernel to, we directly do the dot product on the corresponding range of the padded image with our kernel. This saves a substantial amount of time, at 0.5747s.

The scipy implementation is the quickest, at only 0.0248s. Lots of optimization! I use same padding, and I fill the boundary with 0s to match our implementation. I also verify the correctness of my implementation by convolving an image of myself with a 9x9 box kernel and verifying that all three implementations produce the same output image (with np.allclose).

We see that each of them have a slight black blur around the edges/border. This is due to the fact that we pad with 0s, so the convolution around the edges with the box kernel results in lower-magnitude pixel values.

We also convolve with the derivative filters. We can see D_x recovers vertical edges, and D_y recovers horizontal edges!

2.1

A low-pass, or blur, filter applies a Gaussian kernel to the image. Then, if we subtract this low-frequency, blurred image from the original image, we recover the sharp details that were initially filtered out. This is our high-frequency image; it keeps only those details that were smoothed out by the low-pass filter. We can apply this to the Taj Mahal.

We can then take this difference and add it back to our original image with some weight alpha. This gets us the unsharp mask filter. 2.2

For the hybrid images, one image receives the low-pass filter, and the other receives the high-pass filter, following the practice in Oliva et al. The cutoff frequency of each filter had to be calibrated to for each pair; I calibrated this frequency by adjusting the sigma value of the Gaussian kernel. To compensate, this meant that we had different Gaussian kernel sizes so I could keep the (s-1)/6 ratio. In this case, we compute the kernel size from the sigma, 2 * (3 * sigma) + 1 so the height/width is still odd. I record sigma values with the images; generally, the low-frequency image needed a sigma that was 3-8 units higher than the high-frequency image.

We produce three sets of hybrid images. Here are the first two.

For the third, I’ll show the entire process. We first align the ends of the banana and telephone.

When we apply the low-pass filter to the telephone, we see that circular mask that keeps the central bright region and darkens out the extremities of the image. I chose a sigma of 7 here; I initially had a higher sigma, but the telephone was not recognizable even from a far distance, so I had to reduce it.

In contrast, when we apply the high-pass filter to the banana, we see the reverse effects; the extremities of the image brighten, and the center gets slightly darker. But we can still clearly see it’s the same image with the distinctive pattern on the vertical and horizontal. I chose a sigma of 4 here; this was balanced relative to the choice of the telephone to ensure the banana faded away at a distance but was still clear up close.

The Fourier transformation of the image sum reflects the low-frequency patterns of the telephone (namely, the bright center and verticals/horizontals) and the high-frequency patterns of the banana (the strobe pattern).

2.3/2.4

First, I implement a Gaussian and Laplacian stack. For the Gaussian stack, I choose a constant kernel size and sigma, and continually apply the filter. I.e. G[i] = G[i-1] * (gaussian filter). For the Laplacian stack, I iterate through the Gaussian stack, such that L[i] = G[i] - G[i+1]. For L[0], this is the original image minus the blurred image, to get the resulting details. The last term of the Laplacian stack is just the last term of the Gaussian stack, i.e. L[i] = G[i].

We can plot out the Gaussian and Laplacian stacks for the orange and apple here. I use a kernel size of 23 and 15 levels of the stack, chosen through just experimentation for good blending. For the sake of space, I only plot increments of three, along with the last element of the stack.

Then to blend, we first create a mask. We can construct a variety of custom masks based on an image, or just a straightforward vertical or horizontal mask by simply initializing an array of size image_height x image_width to 0, and setting the left/right half or top/bottom half to 1. I use an implementation similar to align_images to choose a polygonal mask for each image, so we can construct both these vertical and horizontal masks but also any custom nonlinear (but straight-edged) one.

Once we make a mask, we must build a Gaussian stack. Then, to reconstruct, we multiply the Gaussian-transformed mask at index/level i with the Laplacian at the corresponding index for the first image (the one we want to be nonzero for the map). This gives us, intuitively, the part of the aspects of the first image we want to keep, at the frequency corresponding to index i. Then similarly, we multiply 1 - the Gaussian-transformed mask at the same level with the Laplacian for the second image, to extract the aspects of the second image we want to keep. These are added together to form the blended image for that level. If we sum the blended image at all levels, we get the combined image! This makes sense, as at the lowest level, the element in the Laplacian stack reduces to the element in the Gaussian stack, so we’re combining two low-frequency images. Then we add the details captured by the Laplacian at each corresponding level.

As a final reflection: the most important thing I gained from this project was intuition with the low-pass and high-pass filters in relation to hybrid images. Calibrating the sigmas and choosing what image to be low versus high frequency helped me understand how decreasing and increasing the frequency directly influences how you see and perceive the image up close and far away. And with the high-pass filter, I was able to get a better understanding of why this difference operation actually works. Before, it seemed to just come out of left-field, particularly because it's a difference operation that seems not to retain the most important parts of the image! But it's interesting to see how much detail (particularly in the baseball case!) is actually extracted and amplified in the high-frequency case.
